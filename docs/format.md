# Формат базы знаний

Так база хранится в браузере и передаётся файлом JSON. Типы — в [`src/engine/types.ts`](../src/engine/types.ts), разбор чужого файла — в [`src/engine/parse.ts`](../src/engine/parse.ts), смысловые проверки — в [`src/engine/validate.ts`](../src/engine/validate.ts). Полный пример — [`content/example.json`](../content/example.json).

```jsonc
{
  "format": "es-constructor",
  "formatVersion": 1,
  "title": "…", "subtitle": "…", "description": "…", "author": "…",
  "imagesNote": "…",
  "image": { "url": "…", "alt": "…", "position": "50% 30%", "credit": { "author": "…", "title": "…", "source": "…", "url": "…", "license": "…", "licenseUrl": "…" } },
  "settings": { "topCount": 5, "closeGap": 10, "weakPercent": 50, "groupsTitle": "…", "resultTitle": "…" },
  "attributes": [{ "id": "…", "title": "…", "short": "…", "description": "…", "importance": 2 }],
  "groups": [{ "id": "…", "attribute": "…", "title": "…", "tagline": "…", "description": "…", "image": {}, "qualities": ["…"], "firstSteps": ["…"] }],
  "objects": [{ "id": "…", "group": "…", "title": "…", "description": "…", "values": { "<атрибут>": 3 } }],
  "blocks": [{ "id": "…", "group": "…", "title": "…", "description": "…", "questions": [{
    "id": "…", "parameter": "…", "text": "…", "type": "single", "situational": false, "image": {}, "note": "…",
    "reasonTemplate": { "<группа>": "Тебе интересно: {options}." },
    "options": [{ "id": "a", "text": "…", "short": "…", "image": {}, "exclusive": false, "weights": { "<атрибут>": 3 }, "reasons": { "<группа>": "…" } }]
  }] }],
  "rules": [{ "id": "…", "title": "П1", "if": [{ "question": "…", "option": "…" }], "then": { "question": "…", "option": "…" }, "note": "…" }],
  "testProfiles": [{ "name": "…", "story": "…", "answers": { "<вопрос>": ["a"] }, "expectGroup": ["…"], "expectTop": ["…"], "expectClose": false, "expectWeak": false }]
}
```

## Поля

Обязательны `format`, `formatVersion`, списки `attributes`, `objects`, `blocks` и `id` у каждой сущности. Кроме того, у группы нужен `attribute`, у блока список `questions`, у вопроса `type` и список `options`, у правила `if` и `then`. Всё остальное можно не указывать: строки станут пустыми, списки — пустыми, настройки примут значения по умолчанию. Поля, которых нет в этом описании, при импорте отбрасываются. Текст не длиннее 20 000 символов, `id` не длиннее 200.

| Поле | Что это |
|---|---|
| `settings.topCount` | Сколько лучших объектов показывать после каждого ответа. По умолчанию 5 |
| `settings.closeGap` | Если второе место отстаёт меньше чем на столько процентных пунктов, показываются оба. По умолчанию 10 |
| `settings.weakPercent` | Если даже лучшая группа набрала меньше этого процента, итог помечается как слабо выраженный. По умолчанию 50 |
| `settings.groupsTitle`, `settings.resultTitle` | Как называть группы и итог в интерфейсе, например «Направления» и «Твоя направленность». По умолчанию нейтрально: «Группы» и «Результат» |
| `attributes[].importance` | Важность атрибута при сравнении с объектами: его вес wₖ в косинусной мере. Число от 0 до 100, по умолчанию 1 |
| `groups` | Необязательны. Без них система показывает только рейтинг объектов. Группа связана с атрибутом: её итог — доля баллов этого атрибута от максимума. Ниже 0 % доля не опускается |
| `objects[].values` | Выраженность атрибутов у объекта, целое от 0 до 3. Если значения нет, оно равно 0 |
| `blocks[].group` | Группа блока. Блоки без группы считаются общими: при равенстве процентов побеждает группа, набравшая больше в них |
| `blocks[].description` | Показывается над первым вопросом блока |
| `questions[].type` | `single` — один ответ, `multiple` — несколько |
| `questions[].parameter` | Название параметра в рабочей базе данных. Не повторяется |
| `options[].weights` | Правило «параметр + атрибут»: вариант ответа и его веса, целые от −3 до 3. Нулевые не хранятся. Вариант с весами — это одно правило (А1, А2, …), номера считаются сами |
| `options[].exclusive` | «Ничего из этого»: снимает остальные отметки. Только при нескольких ответах. Вес такого варианта с весами других не складывается |
| `options[].reasons`, `questions[].reasonTemplate` | Фразы для объяснения итога, по группам. В шаблоне `{options}` заменяется списком `short` выбранных вариантов |
| `rules[]` | Правило «параметр + параметр» (П1, П2, …): если выполнены все условия `if` (через И), то `then`. ИЛИ — это два правила. Все условия стоят раньше выводимого вопроса, поэтому циклов быть не может, а цепочки работают |
| `testProfiles[]` | Выдуманный человек: ответы и что система должна ему показать. `expectGroup` — итог одна из этих групп, `expectTop` — хотя бы один из этих объектов в тройке лидеров, `expectClose` и `expectWeak` — второе место почти равное, итог слабый. Вопросы, значение которых выводит правило, можно не указывать |

## Картинки

Картинка — только ссылка, файлы в базу не встраиваются. В `url` допускаются `http(s)` и относительные пути, в ссылках `credit` — только `http(s)`. Всё необязательно: если картинки нет, для неё просто нет места на экране, а если она не загрузилась, видна заглушка. Пустой `url` при заполненных `alt`, `position` или `credit` — это картинка без адреса: её данные сохраняются, но на экране её нет.

## Чужие файлы

JSON от другого человека — чужие данные. Импорт собирает базу заново, поле за полем, и отклоняет файл, если типы не сходятся или адрес недопустим. Отклоняет он и файл, где повторяется id или есть ссылка в никуда (вес несуществующего атрибута, правило или тестовый профиль с несуществующим вопросом): в редакторе такое не исправить. Тексты выводятся только как текст. Остальные ошибки (пустое название, значение вне шкалы, условие правила после выводимого вопроса) файл не отклоняют: такая база откроется, но тест не запустится, пока ошибки не исправлены.
