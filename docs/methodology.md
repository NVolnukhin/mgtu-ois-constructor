# Методика: как устроена экспертная система

## Задача

Экспертная система задаёт пользователю вопросы о предпочтениях, возможностях и склонностях. После каждого ответа она ранжирует объекты, а в конце показывает весь рейтинг, объясняет его и, если в базе заданы группы, называет итог. Механизм вывода один на все базы. Атрибуты, объекты, вопросы, правила и настройки лежат в данных, поэтому в конструкторе можно собрать такую систему на любую тему.

Встроенный пример определяет волонтёрскую направленность личности: объекты — виды волонтёрской деятельности, группы — направления, итог — направленность.

| Компонент | Где лежит |
|---|---|
| База знаний: атрибуты, объекты, вопросы-параметры, правила «параметр + атрибут» и «параметр + параметр» | браузер (localStorage) и файлы JSON, формат — [format.md](format.md). Пример — [`content/example.json`](../content/example.json), его описание — [knowledge-base.md](knowledge-base.md) |
| Рабочая база данных: параметры текущего сеанса | браузер (localStorage), у каждой базы своя, просмотр — экран «Рабочая БД» |

| Проверка базы знаний | [`src/engine/validate.ts`](../src/engine/validate.ts): экран «Проверка» и `npm run check`, результаты по примеру — [validation.md](validation.md) |

## База знаний

**Атрибуты.** Свойства, по которым система сравнивает ответы человека с объектами. У каждого атрибута есть важность: его вес при сравнении.

**Объекты ранжирования.** То, что система ранжирует. Каждый объект описан выраженностью атрибутов по шкале от 0 до 3.

**Группы.** Необязательны. Группа связана с атрибутом, а её итог — доля баллов этого атрибута от возможного максимума. Объекты и блоки вопросов могут принадлежать группе.

**Параметры.** Каждый вопрос — параметр рабочей базы данных. Вопрос может допускать один ответ или несколько.

**Правила «параметр + атрибут» (А1, А2, …).** ЕСЛИ параметр получил значение, ТО атрибутам даётся «преимущество». Каждый вариант ответа с весами — одно правило с одним или несколькими заключениями. Варианты без весов правил не дают.

**Правила «параметр + параметр» (П1, П2, …).** ЕСЛИ выполнены все условия, ТО система сама присваивает значение другому параметру, и этот вопрос не задаётся. Условия работают через И, а ИЛИ — это два правила. Все условия стоят раньше выводимого вопроса, поэтому циклов быть не может, а цепочки работают: выведенное значение может быть условием другого правила.

Правил «параметр + параметр» стоит задавать немного. Каждое снимает вопрос, поэтому задаётся не меньше N вопросов, где N — число вопросов минус число разных выводимых параметров. Кроме того, правило отвечает за пользователя, поэтому оно уместно только там, где вывод однозначен. Вероятностные связи между ответами лучше учитывать мягко, правилами «параметр + атрибут»: они не лишают человека права ответить самому.

## Механизм логического вывода

После каждого ответа выполняются шаги 1–3, поэтому рейтинг обновляется сразу. После последнего вопроса добавляются шаги 4 и 5.

**Шаг 1. Прямой вывод по правилам.** Вопросы просматриваются по порядку. Если для вопроса есть правило, все условия которого выполнены, вопрос получает его заключение с пометкой, каким правилом оно получено. Условия стоят раньше, поэтому их значения к этому моменту уже окончательные, в том числе выведенные. Если сработало несколько правил, берётся первое по порядку в базе. Если пользователь вернётся и изменит ответ-условие, вывод пересчитается.

**Шаг 2. Профиль предпочтений.** Срабатывают правила «параметр + атрибут» выбранных и выведенных вариантов. По каждому атрибуту *k* складываются их заключения — это сумма *Pₖ*. По тем же вопросам считаются наименьшая и наибольшая возможные суммы *minₖ* и *maxₖ*. Предпочтение:

pₖ = 2 · (Pₖ − minₖ) / (maxₖ − minₖ) − 1, от −1 (все ответы против) до 1 (все за).

В интерфейсе оно показывается как (Pₖ − minₖ) / (maxₖ − minₖ), от 0 до 100 %. Отсчёт идёт от минимума, а не от нуля: у атрибутов, против которых в анкете нет ни одного ответа, иначе предпочтение всегда было бы положительным, и объекты с этими атрибутами выигрывали бы у всех.

**Шаг 3. Ранжирование объектов.** Профиль пользователя p и атрибуты каждого объекта a сравниваются косинусной мерой сходства, wₖ — важность атрибута:

cos = Σ wₖ · pₖ · aₖ / (√(Σ wₖ · pₖ²) · √(Σ wₖ · aₖ²)), от −1 до 1.

Косинус переводится в совпадение от 0 до 100 %:

совпадение = (1 + cos) / 2.

100 % — профиль объекта в точности повторяет предпочтения, 50 % — не связан с ними, меньше 50 % — свойства объекта скорее противоречат ответам. Перевод линейный, поэтому порядок объектов от него не зависит. Косинус не зависит от того, сколько атрибутов выражено у объекта. Если бы доли предпочтений просто умножались на значения атрибутов и складывались, на случайных анкетах примера почти всегда побеждал бы объект с самым большим числом выраженных атрибутов, а объекты с немногими атрибутами не выходили бы на первое место никогда. Объекты сортируются по совпадению. Если даже у лучшего объекта совпадение ниже 50 %, экран результата прямо говорит, что хорошего совпадения нет.

**Шаг 4. Итог по группам.** Этот шаг есть, только если в базе заданы группы. Для каждой группы берётся доля от максимума: Pₖ / Mₖ, где k — атрибут группы, а Mₖ — наибольшая сумма, которую он может набрать. Побеждает группа с наибольшей долей. При равенстве — та, что набрала больше в общих блоках (блоках без группы), где человек прямо выбирает между группами, затем порядок групп в базе. Если второе место отстаёт меньше чем на `closeGap` п. п., показываются обе группы. Если лучшая набрала меньше `weakPercent` %, итог помечается как слабо выраженный. Оба порога — настройки базы.

**Шаг 5. Объяснение.** Для итога собираются ответы с наибольшим весом по атрибуту группы, и у каждого может быть своя фраза. Для каждого из трёх лучших объектов показывается, какие атрибуты сильнее всего совпали с профилем и какие ему противоречат.

## Проверка

Экран «Проверка» показывает три вещи:

- **Ошибки в базе.** Пустые названия, значения вне шкалы, правила с условием после выводимого вопроса и другое. Пока ошибки есть, тест не запускается. Заметки вроде «атрибут не выражен ни у одного объекта» запуску не мешают.
- **Требования ДЗ 2-1.** Для других задач они необязательны.
- **Тестовые профили.** Выдуманные люди с ответами и ожиданиями: какая группа победит, какие объекты попадут в тройку лидеров. Если после правки базы профиль перестал проходить, правила разошлись со смыслом ответов.

`npm run check` проверяет пример строже:

- **Структура и требования задания.** Те же проверки плюс принципы расстановки весов ниже. Импорт файла и его экспорт не должны ничего терять.
- **Персоны.** Тестовые профили примера, в том числе те, у кого срабатывают правила. Их ответы подобраны по смыслу вариантов, а не по весам.
- **Случайные ответы.** 20 000 анкет. Каждое направление должно побеждать в 20–30 % случаев. Ни один вид деятельности не должен быть первым чаще чем в 20 % случаев, и каждый должен попадать в пятёрку лидеров хотя бы в 3 % случаев.
- **Сданная версия.** Результаты персон и случайных анкет сравниваются с эталоном, снятым со старого движка, точно до 10 знаков.
- **Движок и редактор.** Тесты на придуманных базах: условия через И, цепочки, база без групп, разбор чужих файлов, операции редактора.

Результаты последнего прогона — в [validation.md](validation.md).

## Как устроен пример

Сколько чего в базе примера и все её правила — в [knowledge-base.md](knowledge-base.md). Этот файл собирается из данных, поэтому числа здесь не повторяются.

**Атрибуты.** Сферы (дети и подростки, люди с инвалидностью, старшее поколение, экология) связаны с группами-направлениями и важнее атрибутов стиля: физической нагрузки, работы на улице, эмоциональной нагрузки, регулярности, специальной подготовки, организации и лидерства, обучения и объяснения, творчества и игр, работы один на один.

**Объекты.** Виды деятельности, на каждое направление их поровну: от наставника ребёнка из детского дома до автора экопроекта. Каждый описан значениями всех атрибутов.

**Вопросы.** Общий блок «Мотивы и стиль» и по блоку на направление. Среди вопросов с одним ответом есть ситуационные задачи.

**Веса** правил «параметр + атрибут»:

| Вес | Что означает |
|:-:|---|
| 3 | Сильный прямой признак: выбрано занятие сферы, есть регулярный опыт, готовность к трудностям, лучшее решение ситуационной задачи |
| 2 | Заметный признак: эпизодический опыт, готовность при поддержке, хорошее, но не лучшее решение |
| 1 | Слабый признак: интерес без опыта, одно занятие из списка, общая черта с соседней сферой |
| 0 | Связи нет |
| −1, −2 | Только для атрибутов стиля: ответ говорит против атрибута («предпочитаю помогать в тепле и чистоте» — против работы на улице) |

Принципы расстановки:

1. **Монотонность.** Чем сильнее ответ выражает интерес, опыт или готовность, тем больше вес. Отказ даёт своей сфере 0 и не добавляет баллов другим.
2. **Перекрёстные веса — только при общей черте.** Спокойная беседа и помощь конкретному человеку объединяют работу с пожилыми и с людьми с инвалидностью. Ведение группы и генерация идей объединяют работу с детьми и экопроекты. В вопросах с несколькими ответами стыки замкнуты в цикл: занятия с детьми с особенностями развития, общение с теми, кто с возрастом стал хуже слышать, озеленение двора с пожилыми соседями, экоуроки для школьников.
3. **Баланс сфер.** Максимум по сфере у всех направлений одинаковый, вопросы о стиле на сферы не влияют.
4. **Ситуационные задачи** проверяют понимание специфики направления: лучшее решение — 3, приемлемое — 2, ошибки — 0.

**Правила «параметр + параметр»** заданы только там, где вывод однозначен: например, при противопоказаниях к нагрузке грязная работа исключена. Правил немного ещё и потому, что по заданию вопросов должно задаваться не меньше двадцати при любых срабатываниях.
