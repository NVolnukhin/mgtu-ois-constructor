# Конструктор экспертных систем: что строим

Идея преподавателя после зачёта ДЗ 2-1: превратить прототип в конструктор. Человек собирает в браузере свою экспертную систему, она хранится в localStorage, а другому человеку передаётся файлом JSON. Сервера нет.

Сейчас в репозитории лежит прототип: всё, что ниже, ещё предстоит сделать.

## Решения

Приняты автором проекта 5 ноября 2026 года.

| Вопрос | Решение |
|---|---|
| Охват | Любая тема. Автор сам задаёт атрибуты, объекты и вопросы. Рейтинг объектов есть всегда, группы объектов и итог вроде «направленности» включаются по желанию |
| Базы в браузере | Несколько. На главной: мои базы, «Создать», «Импорт JSON», пример про волонтёрство |
| Импорт | Присланная база сразу открывается как тест, редактор — по кнопке |
| Правила «параметр + параметр» | Несколько условий через И. ИЛИ — это два правила. Цепочки вывода работают |
| Правила «параметр + атрибут» | Как сейчас: вариант ответа и его веса |
| Картинки | Только URL в JSON, файлы в базу не встраиваются |
| Настраивается всё | Вопросы, база знаний, картинки |
| Проверки в первой версии | Ошибки в базе (всегда), требования ДЗ 2-1, тестовые профили. Случайные анкеты не входят |

## Предположения

Пока не обсуждали. Меняются без труда, если автор решит иначе.

- Импорт всегда создаёт новую базу и ничего не перезаписывает.
- Экспорт и импорт — файлом. Ссылка с базой внутри не подходит: пример весит около 92 КБ.
- Картинки необязательны, автор и лицензия у них необязательны. Если картинка не загрузилась, видна заглушка.
- Пример про волонтёрство встроен как шаблон. Его фото остаются в `public/images`, в примере на них ведут относительные URL.
- Формула вывода прежняя. Важность атрибута (сейчас вес сфер 2) и пороги — настройки базы.
- Редактор сохраняет изменения сразу.
- Редактор рассчитан на компьютер, на телефоне работает с прокруткой. Прохождение теста остаётся адаптивным.
- Интерфейс на русском.

## Формат базы (черновик)

```jsonc
{
  "format": "es-constructor",
  "formatVersion": 1,
  "title": "…", "subtitle": "…", "description": "…", "author": "…",
  "image": { "url": "…", "alt": "…", "position": "50% 30%", "credit": { "author": "…", "license": "…", "url": "…" } },
  "settings": { "topCount": 5, "closeGap": 10, "weakPercent": 50 },
  "attributes": [{ "id": "…", "title": "…", "short": "…", "description": "…", "importance": 2 }],
  // Необязательно. Группа связана с атрибутом: её итог — доля баллов этого атрибута.
  "groups": [{ "id": "…", "attribute": "…", "title": "…", "description": "…", "image": {} }],
  "objects": [{ "id": "…", "group": "…", "title": "…", "description": "…", "values": { "<атрибут>": 3 } }],
  "blocks": [{ "id": "…", "title": "…", "description": "…", "questions": [{
    "id": "…", "parameter": "…", "text": "…", "type": "single", "image": {}, "note": "…",
    "options": [{ "id": "a", "text": "…", "image": {}, "exclusive": false, "weights": { "<атрибут>": 3 }, "reasons": { "<группа>": "…" } }]
  }] }],
  "rules": [{ "id": "…", "title": "П1", "if": [{ "question": "…", "option": "…" }], "then": { "question": "…", "option": "…" }, "note": "…" }],
  "testProfiles": [{ "name": "…", "answers": { "<вопрос>": ["a"] }, "expectGroup": ["…"], "expectTop": ["…"] }]
}
```

## Что должно остаться верным

- Условия правила стоят раньше выводимого вопроса, поэтому циклов быть не может.
- Оценка «задаётся не меньше N вопросов» — это число вопросов минус число разных выводимых параметров.
- JSON от другого человека — чужие данные. Импорт проверяет структуру, тексты выводятся только как текст, в URL картинок допускаются только `http(s)` и относительные пути.
- На github.io все сайты аккаунта делят один origin, а значит и localStorage, и его лимит около 5 МБ. Все ключи начинаются с `mgtu-ois-constructor/`. Переполнение хранилища нужно показывать пользователю, а не терять данные молча.
- Сданная версия живёт в репозитории `mgtu-ois` и не меняется.

## Что менять в коде

| Сейчас | Станет |
|---|---|
| `ATTRIBUTE_IDS`, `DIRECTION_IDS`, `STYLE_IDS` в `src/engine/types.ts` — 85 строк в 9 файлах | id берутся из данных |
| `Attribute.group` и `SPHERE_WEIGHT` | важность у каждого атрибута |
| `Direction` с полями `tagline`, `qualities`, `firstSteps`, `activities` | необязательная группа, лишние поля решить при реализации |
| `VolunteerObject` с обязательным направлением | объект с необязательной группой |
| `src/data.ts`: JSON вшит при сборке, синглтоны `quiz`, `steps` и другие, их используют 10 файлов | выбранная база в хранилище и контексте React |
| `STORAGE_KEY` в `src/useQuizState.ts` | свои ответы у каждой базы |
| `Rule.if` — одно условие | список условий: `infer`, проверка, экраны |
| `content/images.json` и `image(key)` | объект с URL прямо в базе |
| `WEAK_PERCENT`, `CLOSE_GAP`, `TOP_COUNT` | настройки базы |
| `validateQuiz` и `REQUIREMENTS` в `scripts/lib.ts` | чистые функции в `src/`, общие для браузера и `npm run check` |
| `scripts/personas.ts` | `testProfiles` внутри примера |
| Тексты про волонтёрство и направленность в `StartScreen`, `ResultScreen`, `KnowledgeBaseScreen`, подвал ДЗ в `App` | нейтральные тексты и данные из базы |

## Порядок работы

1. Формат и обобщённый движок. Пример переведён на новый формат и даёт те же результаты: все 13 персон проходят, проценты те же.
2. Хранилище, главный экран со списком баз, импорт и экспорт.
3. Прохождение теста и просмотр БЗ и рабочей БД для выбранной базы.
4. Редактор: атрибуты, объекты, вопросы, правила, настройки.
5. Проверки: ошибки в базе, требования ДЗ 2-1, тестовые профили.
