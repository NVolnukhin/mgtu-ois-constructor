# Конструктор экспертных систем: что строим

Человек собирает в браузере свою экспертную систему, она хранится в localStorage, а другому человеку передаётся файлом JSON. Сервера нет.

Первая версия сделана: главный экран, импорт и экспорт, тест, база знаний, рабочая БД, редактор и проверки работают для любой базы. Формат базы описан в [format.md](format.md).

## Решения

Приняты автором проекта 5 ноября 2026 года.

| Вопрос | Решение |
|---|---|
| Охват | Любая тема. Автор сам задаёт атрибуты, объекты и вопросы. Рейтинг объектов есть всегда, группы объектов и итог вроде «направленности» включаются по желанию |
| Базы в браузере | Несколько. На главной: мои базы, «Создать», «Импорт JSON», пример про волонтёрство |
| Импорт | Присланная база сразу открывается как тест, редактор — по кнопке |
| Правила «параметр + параметр» | Несколько условий через И. ИЛИ — это два правила. Цепочки вывода работают |
| Правила «параметр + атрибут» | Как сейчас: вариант ответа и его веса |
| Картинки | Только URL в JSON, файлы в базу не встраиваются |
| Настраивается всё | Вопросы, база знаний, картинки |
| Проверки в первой версии | Ошибки в базе (всегда), требования ДЗ, тестовые профили. Случайные анкеты не входят |

## Предположения

Пока не обсуждали. Меняются без труда, если автор решит иначе.

- Импорт всегда создаёт новую базу и ничего не перезаписывает.
- Экспорт и импорт — файлом. Ссылка с базой внутри не подходит: пример слишком большой.
- Картинки необязательны, автор и лицензия у них необязательны. Если картинка не загрузилась, видна заглушка.
- Пример про волонтёрство встроен как шаблон. Его фото остаются в `public/images`, в примере на них ведут относительные URL.
- Формула вывода прежняя. Важность атрибута (сейчас вес сфер) и пороги — настройки базы.
- Редактор сохраняет изменения сразу.
- Редактор рассчитан на компьютер, на телефоне работает с прокруткой. Прохождение теста остаётся адаптивным.
- Интерфейс на русском.

Решения, принятые при реализации:

- **Что изменения сохранены,** показывают строка в шапке редактора и всплывашка. Всплывашка одна, появляется после паузы в правках и не чаще раза в 30 секунд, а если запись не удалась, её нет.
- **Подтверждения — свой диалог,** а не системное окно: Esc, клик по затемнению и «Отмена» отказываются от действия, фокус сразу на «Отмена», на телефоне это лист снизу.
- **Пример нельзя менять.** Редактор примера предлагает сделать копию, она попадает в «Мои базы». Сам пример не занимает места в хранилище.
- **Пока в базе есть ошибки, тест не запускается.** Заметки (например, «атрибут не выражен ни у одного объекта») тесту не мешают.
- **Импорт отклоняет файл**, если не сходятся типы, адрес картинки недопустим, повторяется id или есть ссылка в никуда: в редакторе такое не исправить. Остальные ошибки файл не отклоняют: база откроется, и их можно поправить.
- **Удаление убирает всё, что ссылалось на удалённое**, и заранее об этом предупреждает. Правило без одного из условий изменило бы смысл, поэтому удаляется целиком.
- **Два правила с разными выводами для одного вопроса** — заметка, а не ошибка: при взаимоисключающих условиях это нормально. Если сработают оба, побеждает первое по порядку.
- **Шкалы:** значения объектов — целые от 0 до 3, веса — целые от −3 до 3, важность атрибута — от 0 до 100.
- **Если базу изменили посреди теста,** ответы на удалённое забываются, а тест приводит человека к первому вопросу без ответа. id новых вопросов и вариантов случайные: удалённый id не достанется новому вопросу вместе со старым ответом.
- **Формат дополнен** тем, что нужно примеру: `settings.groupsTitle` и `settings.resultTitle` (как называть группы и итог), `imagesNote`, `blocks[].group` (для выбора при равных процентах), `situational`, `reasonTemplate`, `options[].short`, `testProfiles[].story`, `expectClose`, `expectWeak`.
- **Из направления остались** название, девиз, описание, картинка, «Что пригодится» и «С чего начать». Поле `activities` нигде не показывалось и убрано, `short` совпадало с коротким названием атрибута. Время прохождения считается из числа вопросов.
- **Рейтинг без групп:** итогом становится лидер рейтинга, а подпись итога задаётся в настройках.

## Что должно остаться верным

- Условия правила стоят раньше выводимого вопроса, поэтому циклов быть не может.
- Оценка «задаётся не меньше N вопросов» — это число вопросов минус число разных выводимых параметров.
- JSON от другого человека — чужие данные. Импорт проверяет структуру, тексты выводятся только как текст, в URL картинок допускаются только `http(s)` и относительные пути.
- На github.io все сайты аккаунта делят один origin, а значит и localStorage, и его лимит около 5 МБ. Все ключи начинаются с `mgtu-ois-constructor/`. Переполнение хранилища нужно показывать пользователю, а не терять данные молча.
- Пример даёт те же результаты, что сданная версия: `npm run check` сравнивает их с эталоном `scripts/example-baseline.json`.
- Сданная версия живёт в репозитории `mgtu-ois` и не меняется.

## Как устроен код

| Что | Где |
|---|---|
| Формат базы | `src/engine/types.ts`, разбор чужого файла — `src/engine/parse.ts` |
| Механизм вывода | `src/engine/scoring.ts` |
| Проверки: ошибки, требования ДЗ, тестовые профили | `src/engine/validate.ts`, общие для браузера и `npm run check` |
| Хранилище | `src/storage.ts`, у каждой базы свой ключ и свои ответы |
| Маршруты | `src/router.ts`, адрес после `#` |
| Выбранная база в контексте React | `src/base.ts` |
| Экраны | `src/components/`, редактор — `src/editor/` |
| Пример | `content/example.json`, тестовые профили лежат внутри него |
| Проверка примера | `scripts/check-example.ts`: строже, чем для чужих баз, плюс случайные анкеты и сравнение с эталоном |

## Что не вошло

- Случайные анкеты в браузере: они остаются только в `npm run check` для примера.
- Отмена изменений в редакторе. Запасной вариант — скачать JSON или сделать копию базы.
